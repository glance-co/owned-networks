# Browser client for owned networks

Apache-2.0 browser-safe client, usable by another operator independently of the Glance application. It uses browser WebCrypto Ed25519 signatures and verifies every signed public journal event before deriving text, membership, ownership, delegation and moves through the protocol's shared authority reducer. Unsigned host projections cannot replace these fields. In-session checkpoints reject rollback or a conflicting head already observed. A first-time reader still needs a trusted network ID/endpoint; absent an external transparency/gossip mechanism, a host can withhold a newer valid suffix. This is an availability/freshness limit, not proof of latest global state.

Report commands publish only randomized SHA-256 commitments to their private data. Their signed private sidecars are returned to community moderators and authorized report readers, checked against the commitment, and replayed before displaying report evidence. Public history reveals report occurrence, time and signing identity. This preview is for public networks; it does not promise metadata confidentiality or private E2EE. Public post history, including deleted posts, remains in signed proofs; deletion removes the current projection.

The optional Apache-licensed `./device-profile` module stores the signing CryptoKey in IndexedDB, namespaced to a device profile or explicit local account ID. It proves the public/private key pair before use, never silently creates a missing profile, and refuses to replace an existing profile with a different recovery identity. Glance login and email identity do not confer network ownership. Reading public networks needs neither a profile nor a Glance account. This is device storage, not a password-encrypted local vault; profile locking clears application memory but same-origin code can reopen IndexedDB.

Keys and recovery passphrases are never sent to a network host. Portable backups use WebCrypto PBKDF2-HMAC-SHA256 (600,000 iterations, random 128-bit salt) and AES-256-GCM (random 96-bit nonce, 128-bit tag, format-bound additional data). Import authenticates the backup and proves the private key matches its public identity before use. Matching recovery preserves drafts and read markers. This standard-primitive backup format awaits external review; it is not MLS encryption. Keys are extractable to support encrypted backup; application XSS, malicious client delivery or a compromised device can access them. Lost key/backup/passphrase cannot be reset. Manual same-identity recovery on another device works; key rotation and managed device revocation remain unavailable.

Public communities support profiles, open or owner-approved joining, posts, resources, events with public RSVP choices, and informal nonbinding polls with public votes. Page contents and creation order are derived from verified signed history; unsigned host pagination hints must match. Revision drift requires a fresh first page. Discovery verifies each returned community but cannot prove that a host listed every community. Drafts, unread markers and a pending signed request remain local to the device profile. A pending write or import is signed once, reconciled by read-only history lookup, and explicitly retried with the exact same request. Acceptance is verified at its recorded proof position even after later writes. No timer silently retries or replaces a signing identity.

Any reader can export verified public history, which includes previously removed public content and report actor/time commitments but excludes restricted report sidecars. Only an owner can request the complete migration archive, which also discloses submitted report evidence. Migration requires a committed source freeze, initial destination acceptance while the source remains online, then destination-only writes. The production destination checks a public HTTPS source and durable handoff; loopback browser tests explicitly inject a test-only verifier. Exact replay of an already accepted import does not require the old source to remain online.

Requests omit cookies, reject redirects, use a 15-second timeout and 4 MB response limit. Only HTTPS hosts or explicit local loopback HTTP hosts are allowed. Hosting origins must explicitly permit the browser application's origin with `NETWORK_WEB_ORIGINS`. No Gmail or Glance sign-in is needed for the reference client. This development version verifies cryptographic identity control; verified-email admission has not been bound to the protocol.

This package imports only the adjacent open protocol package and browser platform APIs; the private Glance application is not a runtime dependency. From an open-core checkout with the `packages/` layout and Node 24.14.1, these checks run independently:

```text
npm --prefix packages/v3-network-client test
npm --prefix packages/v3-network-client run build
```

`test/browser-client.test.mjs` in the protocol package checks signatures, backup restoration, tampering, unsafe endpoints, forged projections, rollback, verified pagination, exact receipts, and lost import responses. Additional private-application integration evidence covers actual Chrome IndexedDB persistence, account switching, blocked storage, public feature workflows and a real root API/PostgreSQL round trip; those app-specific harnesses are not required by this package and are excluded from the public core.

A client deployment's CSP determines which hosting origins it can reach. Independent compatible clients/operators need no Glance approval. Private creation stays disabled pending independent security acceptance. Local tests are not evidence of production rollout, provider acceptance, or an external audit.
